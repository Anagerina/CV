---

### Что  было сделано:

1. Немного изменены параметры изначальных аугментаций, а также по рекомендации добавлены `ElasticTransform` и `CoarseDropout`
2. в Resize применены изначальные размеры фотографий `(360*480)`
3. Используется энкодер `"efficientnet-b3"`
4. используется `LEARNING_RATE = 1e-4`, `BATCH_SIZE = 8`, оптимизатор `AdamW` с `weight_decay=0.0001`
5. Используется `Focalloss` со взвешенными классами (для релизации потребовалось реализовать дополнительный класс `WeightedFocalLoss`, который находится в src/lightning_module.py)

---
### Блокнот main.ipynb лежит в папке notebooks

В на первом этапе обучения модель показала результат `mIoU = 0,63`.

Визуализировав IoU по классам (график лежит в plots\output_0.png) стало понятно, что модель неудовлетворительно обучилась предсказывать пиксели редких классов. Так, например, для столбов около `0,06`, для пешеходов не выше `0,4`, для дорожных знаков около `0,5`.

Поэтому в дополнение к Focalloss было преведено взвешивание классов (функция находится в src\utils.py) и после применено к кастомному классу WeightedFocalLoss, упомянутому ранее.

Также для того, чтобы дать модели возможность преждевременно не прерывать обучение, в `early_stop_callback` я повысила `patience = 30`.

Это позволило увеличить метрику до `mIoU = 0.692`

После 2 этапа обучения был повторно визуализироован рост IoU по каждому классу `(график лежит в plots\output_2.png)`.

На графике `output_2` видно, что по каждому классу IoU выходят на плато, модель завершила обучение с отличным результатом.

На финальной оценке с TTA модель показала метрику выше (0.736), чем во время обучения.

Важно отметить, что в валидации с TTA используется только `HorizontalFlip`.

Также из финальное рассчета был исключен класс Void, поскольку его наличие только занижает оценку модели.
Переобучени не потребовалось, я просто рассчитала итоговый mIoU без учета Void.

В конечном итоге после валидации с TTA IoU вырос до `mIoU: 0.736`.
