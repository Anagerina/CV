# Отчет по домашнему заданию CamVid Segmentation.

---
## Финальная метрика IoU модели : 0.736 
---

### Что  было сделано:

1. Немного изменены параметры изначальных аугментаций, а так же по рекоммендации добавлены `ElasticTransform` и `CoarseDropout`
2. в Resize применены изначальные размеры фотографий `(360*480)`
3. Используется энкодер `"efficientnet-b3"`
4. используется `LEARNING_RATE = 1e-4`, `BATCH_SIZE = 8`, оптимизатор `AdamW` с `weight_decay=0.0001`
5. Используется `Focalloss` со взвешенными классами (для релизации потребовалось реализовать дополнительный класс `WeightedFocalLoss`, который находится в src/lightning_module.py)

---

В на первом этапе обучения модель показала результат `mIoU = 0,63`.

Визуализировав IoU по калассам (график лежит в plots\output_0.png) стало понятно, что модель совсем плохо обучилась предстказывать пиксели редких классов. Так например для столбов около `0,06`, для пешеходов не выше `0,4`, для дорожных знаков около `0,5`.

Поэтому в дополнение к Focalloss было преведено взвешивание классов (функция находится в src\utils.py) и после применено к кастомному классу лосса  WeightedFocalLoss, упомянутому ранее.

Также для того, ччтобы дать модели возможность преждевременно не прерывать обучение, в `early_stop_callback` я повысила `patience = 30`.

Это позволило увеличить метрику до `mIoU = 0.692`

После 2 этапа обучения был еще раз визуализироован рост IoU по каждому классу, (график лежит в plots\output_2.png).

На графике видно, что по каждому классу IoU приближаются к своим ассимптотам, модель вышла на плато с отличным результатом.

На окончательной валидации с TTA модельпоказала результат более высокий, чем во время обучения.

Важно отметить, что в валидации с TTA ипрользуется только `HorizontalFlip`.

Также из финальное рассчета был убран класс Void, поскольку его наличие я заметила уже после обучения модели, и чтобы не переучивать ее заново я просто рассчитала итоговый mIoU без учета Void.

В конечном итоге после валидации с TTA IoU вырос до `mIoU: 0.736`
